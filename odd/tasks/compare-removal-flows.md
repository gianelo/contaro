# Compare removal flows for Movements and plan items

## Objective
Address #137 as a design-only decision: draw and weigh at least three genuinely different flows for striking a Movement and removing a Budget item. Do not implement the chosen flow before visual review and a separate implementation issue.

## Premise and constraints
- #137's statement that plan removal is inaccessible is stale: ADR-0047 and the current correction header preserve an accessible 44×44 trash button as a bridge. The work is to design a better discoverable flow, not restore a broken endpoint.
- Movement strike keeps an audit of who did it and requires confirmation; an unplanned Budget item is removed without confirmation today. Neither is a reversible operation today. A paid Fixed item and a closed month do not offer removal (ADR-0034, ADR-0002).
- Artboards must show both kinds, discovery, keyboard/screen-reader path, confirmation separately, undo or its explicit absence, bulk affordance/cost, attribution and paid Fixed exclusion. Consider iOS Safari #107 at 390×664 (ADR-0037). If a gesture appears, it must have a visible alternative.
- Compare three alternatives: A correction-screen detail action (the honest null option); B visible per-row overflow menu on both lists; C explicit multi-select mode for bulk with a visible mode entry. Treat swipe as a fourth candidate only if evidence warrants it; never smuggle a gesture into one of the three.
- Draw alternatives, state UX costs and motivations, run the design build and checks. Ask the maintainer to choose after seeing the artboards. Record the choice in an ADR and open a separate implementation issue only after review; do not guess it.
- Existing Matt Pocock skills, GitHub Issues, runtime screens and source behavior remain unchanged.
